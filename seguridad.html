Seguridad y protección de datos

Última actualización: 14 de octubre de 2026 · Versión 1.0

Este documento resume cómo se protege el sitio, cómo se manejan los datos de los clientes y cómo reportar una vulnerabilidad de forma responsable.

1. Medidas en el sitio

  • Conexión cifrada obligatoria (HTTPS con HSTS): el navegador nunca se conecta sin cifrado.
  • Política de seguridad de contenido (CSP) estricta: solo se ejecuta código propio. No hay anuncios, rastreadores ni scripts de terceros.
  • Protección contra suplantación visual (clickjacking): ningún otro sitio puede mostrar esta página dentro de la suya.
  • Permisos bloqueados: el sitio no puede usar cámara, micrófono, ubicación ni pagos.
  • Aislamiento de recursos: otros sitios no pueden incrustar las imágenes ni los archivos de este dominio.
  • Cortafuegos de Vercel con mitigación automática de ataques DDoS y verificación de bots.
  • Sitio estático: no hay base de datos, formularios ni panel de administración expuestos, y no se almacenan datos personales en el servidor.
  • Correo protegido frente a programas que recolectan direcciones para spam.

2. Datos de clientes

  • Solo pido la información necesaria para cada proyecto.
  • Las contraseñas y accesos que un cliente comparte se reciben por canales privados, se guardan cifrados y se eliminan o devuelven al terminar el proyecto.
  • El código de los proyectos se guarda en repositorios privados con acceso restringido.
  • Las cuentas que administran sitios y proyectos usan contraseñas únicas.
  • Si ocurre un incidente que afecte datos de un cliente, se le informará en cuanto se confirme, junto con las medidas tomadas.

3. Reportar una vulnerabilidad

Si encuentras un problema de seguridad, escribe a pauljared96@gmail.com con el asunto “Seguridad”. Incluye una descripción, los pasos para reproducirlo y su posible impacto. Responderé en un plazo de 5 días hábiles.

Mientras investigas, por favor:

  • No accedas, modifiques ni elimines datos de otras personas.
  • No realices pruebas de denegación de servicio ni envíes tráfico masivo.
  • Da un plazo razonable para corregir el problema antes de hacerlo público.

Los datos de contacto también están en el archivo estándar security.txt.
